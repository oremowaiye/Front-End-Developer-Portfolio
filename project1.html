What it is

A Selenium 4 and Java test automation framework built against saucedemo.com. It covers the flows a real store depends on: signing in, browsing and sorting the catalogue, building a cart, and completing checkout. 45 test cases, running green in CI.

View the live test report View on GitHub

Why I built it

My day job runs on a client codebase I cannot show anyone. This is the equivalent work in public, somewhere I can demonstrate how I structure a suite rather than just claim I can.

How it is put together

Every page of the application has its own class holding its locators and the actions available on it, so a change to the markup is fixed in one file rather than across every test. Tests describe behaviour and read as behaviour. There are no waits in the test bodies, only explicit waits inside the page objects, and a thread-local driver factory so classes can run in parallel.

The negative cases are the interesting ones: locked-out users, rejected credentials, incomplete checkout forms, and reaching the inventory without signing in. Those catch more real regressions than the happy path does. The invalid credential cases are data driven, so one test method covers several combinations.

What it covers

  • Suites Smoke and regression, plus separate API and BDD suites
  • BDD Cucumber features sharing the same page objects
  • API RestAssured checks with a shared spec and a response time budget
  • Flake handling A retry analyser, so a genuine failure is distinguishable from a blip
  • Reporting Allure with severities and screenshots on failure
  • CI GitHub Actions on push, pull request and nightly, Chrome and Firefox in parallel
